# R5 후속 단계 재생

R5에서 4~8단계를 이어서 보정한다. 기본 실행 모델과 R5 원본은 유지한다. 후보의 수락 여부는 [보존 증거](../../experiments/evidence/2026-11-22_r5_stages/)의 최종 보고서와 선택 기록으로 확인한다. `PASS`는 재생·접지·입력·초기 상태 검사를 통과했다는 뜻이며, 모델 개선 수락과 구분한다.

## 입력과 비교

`windows.json`의 28개 구간을 고정한다. 기존 22개 구간에 LON3, LAT6, LONK20, MOVE 3개를 추가한다. 기존 구간의 시작·종료 시각과 명령 원본은 변경하지 않는다. 새 구간은 명령과 실측 정지 상태로 먼저 정하며 후보 결과에 따라 자르지 않는다.

| 묶음 | 구간 수 | 사용 방법 |
| --- | ---: | --- |
| LAT1·SELFCHECK | 3 | 정지 조향과 비이동 회귀 |
| LAT3 직진 | 3 | 저속 구동·타력·방향 회귀 |
| LAT4·LAT5 원선회 | 8 | R5 곡률·속도·회전수 보존 |
| LON2 | 2 | 페달 상승 보정과 반대 방향 확인 |
| LON3 | 1 | 한 구간 안의 제동 40·45·50·55·60% 다섯 조건 |
| LON5·LONK | 4 | 고속 가속·타력 보정과 20/30km/h 입력 확인 |
| LAT6 | 1 | 약 391초 연속 재생, 16·8·4초 주기와 반복 블록 |
| MOVE | 6 | 중간 조향·저속 복합 응답 보정과 다른 기록 확인 |

LON3와 LAT6의 내부 반복마다 상태를 초기화하지 않는다. LAT6 첫 블록으로 조향 액추에이터를 추정하고 두 번째 블록으로 확인하되, 계산 상태는 처음부터 연속한다. 기록된 CAN 명령을 그대로 재생한다. 최초 자세를 맞춘 뒤 실측 위치·속도·방향을 시뮬레이터에 주입하지 않는다.

지표는 관측의 RTK fixed·유효 상태와 고정 시간 구간을 사용한다. 상태 기록의 100ms 초과 공백 전후 100ms는 관측 지표에서 제외하며 명령 재생은 계속한다. LON3에는 약 326ms 상태 공백이 있다. 후보의 오차가 큰 시점을 기준으로 제외하지 않는다. 입력 SHA와 구간 SHA를 각 재생에 남긴다.

모든 자료는 이미 공개한 개발 자료이다. 내부 확인 회차를 논문의 미공개 최종 평가 자료로 부르지 않는다. 명목 시험명과 실제 도달 속도를 구분한다.

## 수정과 판정

`candidate.py`는 부모 해시를 확인하고 설계를 먼저 기록한 뒤 새 모델 JSON을 생성한다. 기존 모델과 설계 파일은 덮어쓰지 않는다. 한 후보에서 페달 표, 제동 표, 타력 저항, 조향 중심 표, 구동 중 저항 표 중 한 응답 그룹만 수정한다. 불합격 중간 후보의 자손도 원인 분리 실험으로 보존할 수 있으나, 전체 회귀를 통과하기 전에는 선택 모델로 승격하지 않는다.

속도·종점·위치·방향·누적 회전수는 `design.json`과 `assess.py`로 개별 비교한다. 평균 점수로 큰 악화를 상쇄하지 않는다. 정지 조향은 추가 오차 `max(기준의 10%, 0.2도)`와 비이동을 확인한다. 고속 중심 조향은 별도로 회전속도 오차도 확인한다. 수치 최적화나 힘 민감도 계산은 후보 제안이며 Unreal 재생 결과와 구분한다.

`brake_response.py`의 동일 속도 구간 감속 비교는 힘 특성을 분리하기 위한 보조 진단이다. 전체 주행의 시간축을 정렬하거나 정지 위치 평가를 대체하지 않는다. 지원 속도 구간은 R5와 실측으로 고정하며 후보에서 빠진 구간도 보고한다.

사용자의 후속 지시에 따라 `shape.py`로 모양과 진행량을 분리한다. 최초 자세 정렬을 그대로 두고, 0.5m 간격 경로점의 양방향 최근접 거리와 진행률 순서에 따른 위치·누적 방향 오차를 계산한다. 좌표를 다시 평행 이동·회전·확대하지 않는다. 같은 원을 여러 번 도는 경우 최근접 거리만 작을 수 있으므로 총 이동거리·누적 회전수·순서 지표를 함께 본다. 진행률 비교는 보조 진단이며 실제 시간축의 속도·위치·종점 오차는 유지한다. 새 수치 수락 기준을 결과에 맞춰 만들지 않고 기존 경고와 모양의 차이를 함께 보고한다.

## 실행 격리와 재현

파라미터 시험의 전용 프로젝트는 `simulator/variants/r5_stages_20261122`, 포트는 `41709`이다. 프로젝트 잠금, 포트 점유 검사, 고유 출력 경로를 사용하고 자신이 시작한 offscreen 프로세스만 종료한다. GUI·MPC·BSW·실차 CAN을 실행하거나 설정하지 않는다. 이 프로젝트는 R5 바이너리를 그대로 사용한다. P0와 원래 R5의 LON2 재생 수치가 정확히 같은지 확인한다.

MOVE 후속 가설용 `simulator/variants/r5_creep_20261122`와 `simulator/variants/r5_creep_viscous_20261122`를 별도로 만든다. 이 사본의 `PoweredCreep.h`와 `ResearchReplay.cpp`에 선택형 저속 선회 저항을 추가한다. 모델 JSON이 프로젝트와 바이너리 해시를 지정하며, 재생기는 세 전용 프로젝트만 허용한다. 같은 전용 포트를 사용해 자동 재생을 순서대로 실행한다. 기능을 끈 NP0는 R5의 LON2·LAT4 L120, NP1은 R5의 LON2에서 차량·조향 텔레메트리의 모든 수치가 정확히 같다. [구현 가설](../../experiments/evidence/2026-11-22_r5_stages/creep_implementation_design.json), [NP0 동등성](../../experiments/evidence/2026-11-22_r5_stages/creep_disabled_equivalence.json), [NP1 동등성](../../experiments/evidence/2026-11-22_r5_stages/viscous_disabled_equivalence.json)을 보존한다.

저속 추가 저항은 네이티브 곡률·속도·실행 명령만 사용한다. 최대 크기는 후륜당 0~15Nm, 완전히 사라지는 속도는 0.2~0.8m/s로 제한한다. 0.15m/s 이하의 속도 계수는 1이며 이후 선형으로 감소한다. 곡률 계수는 `min(1, abs(k)/0.07)^2`, 페달 계수는 기존 83~85% 전이와 같고 제동 중에는 추가하지 않는다. 실제 타이어·제동 원인이 독립 식별됐다는 뜻이 아니다. 질량·COM·관성은 유지한다.

일정한 저속 저항 후보는 거의 정지하거나 다시 과속하는 경계가 나타났다. 세 번째 프로젝트에서는 위 저항에 `min(1, abs(v)/rise_speed)`를 곱하는 선택형 증가 구간을 추가한다. `rise_speed=0`이면 기존 계산을 그대로 사용한다. 양수는 0.05~0.5m/s이며 저항이 사라지는 속도보다 작아야 한다. [가설과 범위](../../experiments/evidence/2026-11-22_r5_stages/creep_viscous_design.json)를 먼저 고정했다.

기록 물리 간격은 0.01초, 준비 조향 구간은 3초, 워밍업은 2초이다. LAT6 전체 길이를 허용하기 위해 전용 ground 재생 검사 상한만 600초로 늘린다. 입력 범위·시간 단조성·자동 비트·접지 검사는 유지한다. 중간 곡률 점 하나를 추가하기 위해 전용 Python 저항 표의 개수 상한을 12에서 16으로 늘린다. 네이티브 벡터의 계산과 유한성·순서·저항 범위 검사는 유지한다.

`run.py`는 같은 후보·입력·모델·바이너리·구간 해시로 완료한 결과가 있으면 재사용한다. `ALL`은 지정한 우선 구간 뒤에 나머지 고정 구간을 추가한다. 전체 검증을 새로 실행하려면 새 실험 ID와 보존 경로를 만들며 기존 증거를 삭제하지 않는다. `audit.py`는 완료한 PASS 재생으로 구간 충족 여부를 판단하고 실패한 시작 시도는 따로 남긴다. `metrics.py`, `assess.py`, `plots.py`의 CSV·그림은 보존한 원본 재생으로 다시 계산하는 파생 자료이다.
